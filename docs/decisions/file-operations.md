# Decisions: File operations and the clipboard

Copy, move and Replace, what protects files while they run, folder sizes, and Paste as File, Copy Contents, Share and Convert Images. Part of the owner's decisions: [the index](../decisions.md) lists the other parts, and [principles.md](../principles.md) says how a decision is weighed and when to ask about one.

- **A full disk ends a paste.** The first "no space" error stops the run, the rest is "Not started", and a partly copied folder is not put in place. There is no free-space check before a paste starts, for now: that is a feature of its own.
- **A file moved to another disk goes even if the disk refused an extended attribute.** A refused attribute is skipped on purpose (most files carry `com.apple.provenance`, and FAT and exFAT refuse many); only a resource fork that can't be written fails the copy.
- **A move to another disk is written out to that disk before the original is deleted.** Copied, an item may be only in memory or in the drive's own cache; deleted then, a power cut leaves it nowhere. A file is flushed as it is copied (`F_FULLFSYNC`, about 5 ms a file on an internal SSD), one put in place of another too; a folder once, whole, when it is in place (`sync_volume_np`, some 30 ms), so a folder of thousands costs one flush; files moved one by one, and a folder merged into one that is there, pay for each file. A disk that can't be told to flush (some network disks) is left to itself, and a copy that fails to be written out keeps its original and says so. Before, the original went once the copy had the same kind and size.
- **The journal entry that guards a moved item's only copy is flushed to disk.** Other journal entries aren't, for speed; this one is written once per Replace.
- **A folder moved to another disk keeps its journal entry until the originals are gone.** After a crash in between, recovery says what was left of the original and where.
- **Progress counts are taken back when a Replace is undone or asked again**, so the count done never passes the total.
- **A conflict question takes one answer.** If the answer can't be sent, the question stays, its buttons disabled, and Escape still dismisses it.
- **A Replace row in the paste review says what goes to the Trash**, as its footer does, not "Deletes".
- **A copy is checked for its source's whole resource fork.** copyfile was once seen to report success with no fork at all on a full disk, its status callback told nothing; why was not found (16 full runs didn't bring it back). One way to it was found since and closed (2026-11-15): a copy that copyfile ended in failure without setting errno was told as done, as the errno read after it was returned as the result, and it now fails with ENOSPC or EIO as the fork's check says, never as a copy that is done; whether that was what had been seen was not shown. Whatever the cause, a copy that reports success with less of the fork than its source fails (`ft_check_resource_fork`): with ENOSPC when the destination's disk hasn't the room for the fork, EIO otherwise. The caller removes it as any failed copy.
- **What a later try of leftover work finds is told as at start.** A move found in place, a rename put back, a folder put in place: shown under "Work was cut short when File Trail last stopped", before the items now in place, in a dialog of their own. Each message is told once, counting what the start already said, so an entry whose record can't be removed doesn't repeat itself every minute.
- **Calculating a folder's size is best effort** (2026-11-17). A sub-folder gone, replaced by a file or a link, renamed or gone with a folder above it while the walk runs, one a folder above it was swapped for a link to reach (it would be outside the folder measured), one it has no permission to read, and a listing broken part way by a read error are left out, and the size of the rest is shown: the size is approximate anyway (changes made outside the app leave it as measured), and failing gave no size at all, most often in `~` and `~/Library`, where apps add and delete files all the time. A measurement fails only when the folder itself can't be measured: it is gone, isn't a folder, can't be opened or listed, or the walk can't start. The code keeps whether each size is complete or partial, and why (something changed, no access, a read error), with nothing shown for now, so something can be done with it later. This replaces the rule that a sub-folder replaced, or gone with the folder it was listed in, or a listing broken part way, failed the walk as incomplete; only a sub-folder removed from a folder still in place was left out.
- **A folder size asked for is never stopped by another request** (2026-11-16). Calculate Size on a second folder, by any route, waits for the first instead of stopping it: both were asked for, and Finder measures both. Only Stop, closing the window, or quitting end it early; a write that makes it outdated has it run again. Asking again for a folder being measured or waiting, Recalculate included, joins that measurement, whose answer is as fresh as a new one's (2026-11-17: this line said Recalculate on the same folder ended it early, against the plan and the code, which join). At most 10 asked requests wait, for the whole app, a run of several folders counting as one; past that the oldest waiting one is dropped, never the one running, so a burst of requests doesn't keep the Mac walking long after they stopped mattering. The plan is [records/folder-sizes.md](../records/folder-sizes.md).
- **Folder sizes the app measures by itself give way** (2026-11-16). An automatic walk (the Info panel's or the Info Row's) of a window not in front is stopped for any size asked for and for the front window's automatic one, and waits again while its window still describes that folder. When the view that asked moves to another folder or closes, its request leaves the queue, or stops if it runs. A tab behind another tab, or a minimized window, drops its automatic walk. A window you aren't looking at shouldn't make the one you are wait minutes.
- **Folder sizes changed outside the app stay as they were measured** (2026-11-16) until measured again, by the refresh button beside the size or Calculate Size. The app's own writes still adjust or forget them. Forgetting the sizes of folders the watchers see change, or marking them as possibly outdated, was weighed and not taken.
- **Calculate Size measures again, one folder or several** (2026-11-17). With several folders selected it measured only those with no size and left the rest, so on a selection already measured it did nothing, where on one folder it always measured again; the same command now does the same thing. A folder being measured or waiting is left to finish. The cost is accepted: a large selection is walked whole each time it is asked for. The Info panel's Calculate, which shows only while a size is missing, still measures only what is missing; its refresh button measures all again.
- **A folder size waiting for another to finish says "Waiting…"** (2026-11-16), apart from one being measured, so a long wait behind another folder doesn't look like a slow walk. The folders of a Calculate Size on several whose turn hasn't come say so too (2026-11-17; they showed "--"). In the Activity list such a request is one row from its first folder to its last, "11 folders", saying how many are done and filling as they are, and ending as "Done" or "Stopped"; the folder it is on has no row of its own, and its Stop stops them all. A row "3 more folders" beside the folder being measured, tried first, ended as "No longer waiting" between rows that said "Done", which read oddly.
- **While the Activity list is open no row changes place** (2026-11-17). A row whose item ended stays where it was, dimmed, saying how it ended ("Done", "Stopped", "Couldn't calculate"), with no Stop, and nothing is taken out of the list but the row of a measurement the app started by itself, whose state the Info panel or the Info Row shows already; one whose turn came says so where it is; what is new goes to the end; and the list stays open with nothing left running, the ring an empty circle under it until it closes. Opened again it shows only what runs, in its usual order. It shows six rows at once and scrolls past that, under its header, so a long list (rows that ended stay, and ten sizes can wait) is not a tall one. Rows that moved up as one ended put the next row's Stop under a press aimed at the one that went; ignoring Stop for a moment after a move, tried first, still let the list jump and dropped presses without a word. The ring's count has nothing behind it at rest, so it looks the same with one thing running as with several: the owner doesn't want its background to change.
- **A folder size says nothing of folders it has no permission to read**, which count as empty, as in Finder (2026-11-16). Hard links counted each time they are met, and iCloud files not on the Mac, stay counted as they are.
- **New Folder with Selection (⌃⌘N, Finder's key) puts the selected items in a new folder beside them, and one Undo takes it all back** (2026-11-19). It is in File after New Folder and on an item's right-click menu, for items of the folder on screen only (not search results, not the Trash). The folder takes the next free "untitled folder" name and opens for naming, as New Folder's does; each item is a rename into it, so nothing goes through the paste review. One Undo moves the items back out, then puts the folder in the Trash, as in Finder; it asks first only when something else was put in the folder since. An item that can't be moved leaves the others in, and is told of; when none could, the empty folder is removed again. This differs on purpose from a folder typed in Move To or Extract To, which is a New Folder of its own and undone apart from the move.
- **New File makes a file from a template, with its own date** (2026-11-19). File ▸ New File, and New File on the folder's right-click menu, offer Text File (an empty "untitled.txt"), each file of the Templates folder (`~/Library/Application Support/com.filetrail.native/Templates`, opened by the last item of the submenu, made the first time), and Open Templates Folder. Only plain files of that folder are listed (no folders or packages, nothing hidden), by name; the list follows the folder as files are added, removed or renamed. A template's contents are copied into a new file in the folder on screen, so it is dated now and takes none of the template's tags; the name is the template's, numbered when taken, and it opens for naming. Undo moves it to the Trash, as Paste as File's. New Text File has no key until one is set in Settings.
- **Paste as File saves the image or text on the system's clipboard as a new file**, with ⇧⌘V (changeable in Settings) from Edit ▸ Paste as File and the menu of the folder's empty space. It is the only command that reads the system's clipboard (Copy Contents is the one that writes a file's image or text to it): ⌘V still pastes only what was copied in File Trail (see "File Copy, Cut and Paste use the app's own clipboard"). Not ⌥⌘V, which is Finder's Move Item Here: pressed after ⌘C out of that habit, it would write whatever the system's clipboard held. The file goes into the folder on screen, named "Pasted Image.png" or "Pasted Text.txt" (numbered when taken), and is renamed in its row as New Folder's is; Undo moves it to the Trash. The menus name what it would write ("Paste Image as File", "Paste Text as File"). Plain text wins over an image, as a copy from a document or a spreadsheet carries a picture of it too, unless the text is only an address (a browser's Copy Image). An image keeps the bytes it was copied as (PNG, JPEG, HEIC, GIF), so nothing is encoded again; one copied only as TIFF is written as PNG. Of several formats, the first in the clipboard's order is taken, as the app that copied it lists its own first, and TIFF only when there is no other: a HEIC copied with a PNG beside it is saved as the HEIC. Text is written as plain UTF-8 `.txt`, styled text included. Files copied in another app are refused with a toast, never written as their icon or name. Nothing is asked first, as the file is new, replaces nothing and can be undone, except before writing what a password manager marked as private (`org.nspasteboard.ConcealedType`): Cancel is the default there. No settings: a choice of image format was turned down, as forcing PNG makes photos several times larger and forcing JPEG blurs screenshots' text and drops transparency. Text that is only spaces and line breaks doesn't count as text when an image is there too: the image is what is pasted.
- **Copy Contents puts the image or text of one file on the system's clipboard**, to paste in another app, with ⇧⌘C (changeable in Settings) from Edit ▸ Copy Contents, the file's right-click menu and the Info panel's quick actions. ⇧⌘C pairs with Paste as File's ⇧⌘V; in Finder it opens Go ▸ Computer, and pressed out of that habit here it only replaces the clipboard. It leaves the app's own clipboard alone: ⌘C, ⌘X and ⌘V still copy and paste files. The menus name what it would copy by the file's kind ("Copy Image", "Copy Text"); a name that doesn't say (no extension, a kind the system doesn't know, or one that names either: `.key`, a key or a Keynote document, and `.crt` and `.cer`, a certificate in text or in binary) shows "Copy Contents" and the file is read for an image, then for text. A kind that is neither (a PDF, an archive) is left out of the right-click menu and the Info panel; from the menu bar it says so in a toast. One file only. It only reads, so it runs in search results, in the Trash and while a file operation runs. An image goes on as its own bytes under its own type, with a PNG copy, turned as its orientation says, for any format but PNG and JPEG, as many apps read only PNG; the file's address never goes on, so other apps paste the picture, not the file. Text is read as UTF-8, or UTF-16 with its byte-order mark, and anything else (a zero byte, another encoding) is refused rather than guessed; an RTF file goes on with its styles too. SVG is copied as its markup, `.ts`, `.pem` and other text the system calls something else as text. Up to 10 MB of text (more holds up most text fields) and 100 MB of image. A link copies what it points to. A copy says so in a toast, and "Copying…" shows when a slow disk holds it up past half a second; the copy asked for last is the one that lands. Before copying a name that usually holds a password or a key (`.env`, `.env.*`, `*.env`, `.netrc`, `.npmrc`, `.pgpass`, `.htpasswd`, `credentials`, `kubeconfig` and `config` in a `.kube` folder, `*.pem`, `*.key`, `*.p8`, `*.ppk`, private SSH keys but not their `.pub`), it asks, Cancel the default, and marks the text as private (`org.nspasteboard.ConcealedType`) so clipboard history apps leave it out. A link is asked about for its own name or for the name of what it points to, and a name whose extension says image never is. No settings.
- **Share… shows the system's share popover for the selected items, as Finder's does**, from File ▸ Share…, the right-click menu (after the copies, as Finder has it after Copy), the Info panel's quick actions, and a Share button that can be added to the toolbar; no key until one is set in Settings. It is `NSSharingServicePicker`: the items' icon, name and kind at the top, then AirDrop, Mail, Messages, Notes, the share extensions installed, Copy and Edit Extensions…, all as macOS chooses them for the items, so nothing is listed, kept up to date or filtered by the app. The popover hangs under the button pressed, else under the lead item of the selection in the list, else from the top of the list when that item is scrolled out of sight. Files and folders, one or several, in a folder or in search results; it only reads, so it runs while a file operation runs. Not for items in the Trash, which are only taken out or deleted for good, whichever way Share is asked for (a key set for it too), nor from the right-click menus of the folder tree, the favorites or the list's background, as in Finder. The Info panel shares the item it shows, whatever brought it there: a selected item, the folder on screen when nothing is selected, or a folder of the tree or the favorites shown with Show Info; a folder is shared as any item is, and the panel names what its button acts on. A submenu listing the services in the right-click menu, as Finder showed before macOS 13, would need `NSSharingService.sharingServices(forItems:)`, which is deprecated.
- **Convert Images makes new image files from the selected ones, in another format or at another size**, from File ▸ Convert Images…, the right-click menu and the Info panel's quick actions, with no shortcut until one is set in Settings. It is offered only when every selected item is an image the system can read (JPEG, PNG, HEIC, AVIF, WebP, JPEG XL, TIFF, GIF, PSD, camera RAW and the rest ImageIO reads; not SVG or PDF): with a folder or any other file among them, the right-click menu and the Info panel leave it out and the File menu shows it grayed, so a selection is never converted in part. The kind is judged by the name, so the menus stay instant; a file that can't be read once converting starts is listed with the failures. A sheet chooses the format (JPEG, HEIC, PNG, TIFF, AVIF), the quality for JPEG, HEIC and AVIF, the size, and whether to keep the metadata, with removing the location apart; it remembers the last choices. Without the metadata, none of it is written in any format: not the camera's (make, model, dates, serial number), the location, the caption data, a PNG's text nor the XMP, only what the picture needs to show as it did: its orientation and color profile. With the metadata, a resized image keeps all that one at its size keeps (the camera's, the location, the caption data, a PNG's text, and XMP of its own besides), its size and orientation written anew; removing the location takes the GPS position and the place names (city, state, country, place in the city) out of the caption data and the XMP alike, whatever the size, and with them the places only the XMP names (the caption data's newer fields: the place shown, the place the picture was made in) and a position a camera wrote under a name of its own (a drone's `GpsLatitude` and `GpsLongitude`: any XMP field outside EXIF's whose name starts with "gps" or holds "latitude" or "longitude"). A picture in CMYK or in gray made smaller stays in CMYK or gray, with its profile, in the formats that hold one. Stop pressed while a picture is being encoded writes nothing of it, the last picture of a run too. A custom size made smaller only to fit the one picture converted is remembered as it was, and Convert is off when none of the files can be read as a picture. The size is Actual Size, Fit Within a longest side (3840, 2560, 1920, 1280 or 640 px), Scale (75%, 50%, 25%) or Custom: a width and a height in pixels or percent, with Scale Proportionally. A picture comes out exactly the size worked out for it: the side that meets a Fit Within or a box is that size, never a pixel more, and the other the nearest whole pixel to its shape. Proportional, a custom size is a box each image fits inside in its own shape, as one height can't suit images of different shapes; not proportional, every image becomes exactly that size, and the sheet warns when the selected images don't all have the same shape, as it stretches them differently. No image is ever made larger, in its width or its height: enlarging can't add detail (ImageIO only shrinks, and Lanczos through Core Image makes a picture larger but soft), so it was left out. A custom percentage goes up to 100%, and one typed higher becomes 100% when the field is left, with a note. For one image, the Fit Within sizes at or above its longest side are grayed in the pop-up, with its size beside them, and a custom width or height larger than the image's becomes the image's when the field is left, with a note giving its size. For several, Fit Within and a proportional custom size shrink the images larger than the box and keep the others at their size, converted only, as each still meets what was asked; the sheet says how many are made smaller and how many already fit. An exact size (not proportional) that any of them is smaller than, in its width or its height, can't be met without enlarging, so Convert is grayed and the sheet says how many are smaller, as converting only the others would be a partial conversion. Actual Size keeps every image's size, and converting to the same format at Actual Size is allowed, for another quality or without the metadata. Each new file goes beside its original under the same name with the new extension, numbered when taken ("Photo 2.heic"), in search results too; nothing is replaced, the originals are never touched or offered to the Trash, and one Undo moves the new files to the Trash. It runs as a file operation, with the progress card, Cancel, and the files that failed listed at the end. A resized image is turned upright; the color profile, the 16-bit depth for PNG and TIFF, and an HDR gain map for HEIC, JPEG and AVIF are kept, and TIFF is compressed (LZW). JPEG has no transparency, so a transparent image gets a white background, and an animation or a file of several pages gives its first frame; the sheet says each. Only the system's ImageIO, with no library added: it reads WebP and JPEG XL but writes neither, and WebP through Google's libwebp was put off. A choice of where the files go (the other pane, any folder) was turned down for now.
