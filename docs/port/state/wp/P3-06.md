## Goal

The local write operations, ported exactly, through P3-05's slot and wired to the UI.
- **Move to Trash** (file-operations.md §1.5):
  - item by item, carrying on past failures; already gone counts as done;
  - the Trash's own refusal names the item; locked items; cancel stops;
  - on a disk with no Trash it asks, then deletes for good (B-CLIP §15 wording);
  - no re-trashing; one undo unit per trashed item, with its Trash path.
- **Delete Immediately** (§1.6): only inside a Trash, or for an item that just failed to go to a Trash-less disk. It asks first, with Cancel as the default. Partial failures and plain-words errors.
- **New Folder** (§1.7): the next free "untitled folder" name, compared without case where the disk ignores case; made only if the parent exists; then edited in its row. Ask before a name with a leading dot would hide it. Never inside the Trash.
- **Rename** (§1.8):
  - exclusive, refusing a name taken after the check;
  - case-only changes on a case-insensitive disk through a plain rename, and normalization-only changes;
  - hard links; FAT32 empty files;
  - the "hide with a leading dot" question;
  - a finished rename is never reported failed;
  - the refusal texts go to the rename field.
- **Empty Trash** (§1.10) through `TrashState` (P2-05) in the slot: refused while busy; doesn't hold up quitting; windows told after it ran or was tried, not when refused; clipboard items that were in the Trash dropped; the Finder-permission explanation.
- **Guards**: refuse the disk, system folders, a volume and the home folder; Trash rules (nothing pasted, moved or made in it). Use `Paths` and `WriteEffects` from P1-01.
- **Folder sizes and caches**: adjust folder sizes and forget caches before each terminal event, in the order of §3.6 "Release" and §1.5's `removedItems`, through P3-05's coordinator. It already does this for the paths a write reports, so report the right paths.
- **UI wiring**:
  - Fill `WindowWriteActions` rename, newFolder, trash, deleteImmediately and emptyTrash.
  - Connect P5-05's inline rename commit seam (a closure on the window) to rename, and New Folder to editing the new folder's name in its row (also while the list is filtered). P5-05 may not be merged yet: check main for the seam first. If it is missing, build everything else, test rename and New Folder at the `WindowWriteActions` level, and list the missing hookup under blockers. Don't write a rename field of your own.
  - Use P3-05's `WriteDialogs` seam for the questions and refusals.
