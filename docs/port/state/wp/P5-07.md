## Goal

Search as you type, ported exactly (B-SRCH), on P2-06's `fd` service (`FdSearchRuntime`, its `results(for:)` stream, `SearchResults`):
- **Starting** (B-SRCH §1): live search once the trimmed text has at least 2 characters and the keyboard has been still 400 ms; Return; the thresholds.
- **Refinement** (§2, `SearchRefinement`): a longer query narrows the results already found instead of searching again; results never show under another query's text.
- **Scope** (§3, §7): from the current folder, or widened to Home, the volume or Macintosh HD. The results bar: "Search:", the segmented scope, the filter field "Filter by name or folder", Stop with a spinner after 400 ms, Done, and the banner "Showing the first 20,000 matches." (ui.md §1.5).
- **The search field** (§4, ui.md §1.2): the capsule P5-01 placed:
  - Return runs; ↓ moves into the results; Esc ends search mode or drops a draft;
  - the clear button; the accent border and focus ring while active; the same width focused or not;
  - ⌘F focuses it, from the list filter too (P5-05);
  - edit menu commands go to the field while it has the keyboard.
- **The options menu** (§6, ui.md §3.10): Match Name or Full Path; Plain Text, Glob or Regex; Search Subfolders; Skip .git; Skip Git-ignored. Keyboard-opened versus mouse-opened focus. The search preferences.
- **Results** (§8, §9):
  - in any view, with their own view mode (`searchViewMode`, default List), columns (Folder "src › renderer", widths, order) and sort (name, path, kind);
  - the status line; the empty, "Searching…", "No matches", "Incomplete pattern" and "Search failed" states.
- **Highlight** (B-SEL-182, 183): the yellow mark (underlined on a selected row), smart case, none for glob and path searches, mapped onto middle-truncated labels.
  - Make `JSRegExp` public, or add a public highlight helper on it, and switch `SearchResults.highlightPattern` to it. Report D-011 as resolved under deviations; don't edit `DEVIATIONS.md`.
- **Working with results** (§11, B-SEL-087..095): open, Reveal in Folder, the filter and selection rules.
- **Show, hide and clear** (§5): Show Last Search Results.
- **Tabs** (§12, B-VIEW-143, 174):
  - one search session per tab;
  - a background tab's search keeps running: its results stream in, and it says when it finished;
  - a tab that comes back resumes, re-runs a lost answer, or searches what was being typed;
  - the tab label (P4-02 has the text) and its magnifier.
- **Running** (§10, §13): the session counter; cancel with SIGTERM; every `fd` killed at quit (P2-06).
- **Search mode elsewhere** (B-NAV §18): sort commands left to the results bar. The toolbar title "Searching “X”" (P5-01) and the sidebar's search mode (P5-02) are theirs to draw: expose the session's search state on `ExplorerWindowContext` (add members only, keep the existing ones) and check they follow it.
- **Performance:** first results about as fast as the original (PLAN.md §4, relaxed 2026-10-14; `tools/bench` measures about 40 ms today). Report it; don't optimize past that.
- Register `prefs` handlers for the `search*` keys and `searchViewMode` with `AutomationPrefs.register`, from your own code under `#if DEBUG`.
