## Goal

Replace and crash recovery, ported exactly. Pasting must never destroy: the person never ends up with neither item (file-operations.md §3.1).
- **Replace** (`executeReplace`). Fill the seam P3-03 left:
  - the new item is staged under a hidden name;
  - the old item goes to the Trash, or is deleted for good only when the disk has no Trash and the person confirmed;
  - the swap is made with exclusive renames;
  - folder Replace checks identity;
  - file and folder Replace, packages and links, locked items;
  - a replacing move on the same disk and across disks;
  - Replace over another item of the same paste is refused;
  - the Replace journal entry is written before staging and cleared after the swap;
  - the undo log steps of a Replace: Trash location, then the new item (§4.2).
- **Recovery** (`copyPasteRecovery.ts`, and `recoverWrites` in bootstrap `writeJournal.ts`):
  - it runs at startup, before any write service exists, giving each disk 3000 ms to answer;
  - it finishes or rolls back each entry as §3.5 and checklist J say: put a moved item back, finish a complete copy, remove an unfinished one, leave unreachable entries;
  - it removes the parts of large files left by a crash;
  - it reads v0.4.3 legacy entries;
  - it posts the hidden-item notice;
  - it forgets folder caches only when something changed (through injected closures for `DirectoryService`'s cache and `FolderSizeAdjust`);
  - it never throws.
  - Port `retryRecovery` and `RECOVERY_RETRY_INTERVAL_MS` too: running inside the coordinator's `runWriteAlone` (an injected closure), deferring while another write runs, and a 60 s retry (injected timer) until the journal is empty, only for entries left at start. P3-05 only calls them from the app's startup.
  - Keep `batch_rename` entries readable and written back untouched; their put-back is P3-08's.
- **Crash injection (Swift side).** At the n-th journal write, the engine freezes: it never resumes and runs no cleanup or `defer` code, which is what SIGKILL does. Then the harness runs the Swift recovery on the same folders and compares the recovery outcome.

**Differential.**
- Empty P3-03's `PendingReplace.swift`. Every case of every `exec-*` suite must match, `exec-crash` included.
- Add **`exec-crash-volumes`**: a crash at each journal write of a folder Replace and of a cross-disk folder move, on each disk image (`apfs`, `apfs-cs`, `hfs`, `fat32`, `exfat`), then recovery.
