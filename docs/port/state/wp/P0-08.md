## Goal

Parity status that moves by script rather than by hand, plus a disk-image helper that every real-filesystem Swift test can use. This closes phase-0 critic gaps 8, 9 and 10.

## You own

- `tools/parity-matrix/`, `docs/port/parity/`.
- `Tests/FTTestSupport/DiskImage.swift`, `Tests/FTTestSupport/LargeFileTests.swift`.

## Do

1. **Citations.** A Swift test cites the original cases it ports with a comment `// T-1a2b3c4d` (one or more ids) on the line before its `@Test`, or inside its body. A UI-row test can also cite `F-123` ids.
2. **`tools/parity-matrix/sync.ts`** (Bun):
   - Scans `Tests/**/*.swift` for `T-` and `F-` citations and validates them. An unknown id is an error, reported with file:line.
   - Runs `swift test --parallel` with JSON or xunit output (whichever SwiftPM supports; parse it), or reads the last result from `build/logs/` if `--no-run`.
   - Updates `docs/port/parity/tests.tsv`:
     - the `swiftTest` column gets the citing test names;
     - status becomes `ported` when cited and `passing` when every citing test passed;
     - a row a test marks `// covered-by-feature F-123` or `// N/A T-... <reason>` gets that status and the note.
   - Updates `features.md` (below).
   - `--check` fails if the files would change or if any citation is invalid.
   - It is idempotent and merges with any manual notes.
3. **`features.md` columns.** Make them `ID | Feature or behavior | Spec | Planned WP | Tests | Scenario | Status`, keeping all existing rows and their order. Tests and Scenario are filled by `sync.ts` from the citations and from `tools/capture/scenarios/*.json`, whose top-level `features: ["F-…"]` key gets read. Status becomes `done` when the row has a passing test or a passing scenario, and `partial` when it has some but not all.
4. **`report.ts`.** Show ported and passing counts per class and area, and feature status per area. Keep it compact; `state.py status-md` embeds it.
5. **`FTTestSupport.DiskImage`.**
   - `DiskImage.withVolume(.fat32 | .exfat | .hfs | .apfs | .apfsCaseSensitive) { volumeURL in … }`, async throwing. It clones the cached blank image with `tools/fixtures/disk-images.sh clone`, or the same `cp -c` logic in Swift, then attaches it with `hdiutil attach -nobrowse -noautoopen -plist` and detaches with `-force` on exit, even on throw.
   - It tags tests that use it so they can be skipped when `FILETRAIL_NO_DISK_IMAGES=1`.
   - `LargeFileTests.enabled` reads `FILETRAIL_LARGE_FILE_TESTS`. Use it with Swift Testing's `.enabled(if:)`.
6. **Self-tests.** Mount each filesystem kind, write a file, check that `volumeSupportsCaseSensitiveNames` matches the kind, and detach. Cite nothing.
7. **Short docs** in `tools/parity-matrix/README.md`.
