## Goal

A reproducible build of the original Electron app to compare against, plus the fixture trees and blank disk images that tests, benchmarks and screenshots share. Everything heavy lives in `~/Library/Caches/filetrail-port/`, outside every checkout.

## You own

- `tools/reference/` and `tools/fixtures/`.

## Do

1. **`tools/reference/setup.sh`** builds the reference app into `$CACHE/reference/electron`, where `CACHE=${FILETRAIL_PORT_CACHE:-~/Library/Caches/filetrail-port}`. It is idempotent: a stamp file records the commit and success, and a second run that finds the stamp prints `up to date` and exits.
   - Read the pinned commit from `docs/port/state/orchestrator.json` (`referenceCommit`).
   - `git clone` `/Users/tcmudemirhan/src/tsproj/filetrail` (a local clone; the source checkout stays untouched) into `$CACHE/reference/electron`, then check out the pinned commit, detached.
   - `bun.lock` is gitignored in the original. Copy it read-only from `/Users/tcmudemirhan/src/tsproj/filetrail/bun.lock` into the clone, then run `bun install --frozen-lockfile`. If the frozen install fails, fall back to a plain `bun install` and print a warning.
   - Build the native addon with `bun run --cwd apps/desktop build:native`, then the app with `bun run desktop:build`.
   - Smoke-test the build by running the original's own Playwright smoke spec in the clone (`bun run --cwd apps/desktop test:smoke -- smoke.spec.ts` or the equivalent). If Playwright can't launch Electron here, record that in the summary rather than failing the whole script.
2. **`tools/reference/run.sh [--user-data-dir DIR] [FOLDER]`** launches the built reference app in development mode the way the original's `scripts/start.sh` does, without rebuilding. Read that script to see how.
3. **`tools/fixtures/generate.ts`** (run with `bun`): deterministic fixture trees under `$CACHE/fixtures/`. It is idempotent per tree, using a version stamp.
   - **`lighthouse/`.** The demo project in the original README's screenshots. Look at `/Users/tcmudemirhan/src/tsproj/filetrail/docs/screenshots/*.png` and recreate the visible tree under a folder named `Lighthouse`: the `app/{dist,node_modules,src/{components,lib,pages},tests/{e2e,fixtures}}` layout, `data/exports`, `design/screens`, `docs`, `infra`, `mobile`, `photos`, `scripts`, and the file names, sizes (byte counts as shown) and relative ages visible in the screenshots. All mtimes are offsets from a fixed `FIXTURE_NOW = 2026-10-13T14:38:00` local time, which the Swift and Electron captures will freeze their clocks to. Add a few real images (generate small PNGs/JPEGs with gradients so Quick Look thumbnails differ) under `photos/` and `design/screens/`.
   - **`bench/`.** Folders of 300, 3,000, 30,000 and 100,000 files with mixed names (including numbers and non-ASCII), and a deep tree of about 200,000 files and 20,000 folders for folder-size timing.
   - **`names/`.** Edge-case names: NFC vs NFD accents, emoji, 255-byte names, leading dots, `.localized`, packages (`.app` bundle skeleton, `.key`-style document package), a symlink to a folder, a broken symlink, a Finder alias created with `osascript` if possible, a locked file (`chflags uchg`), and a file with a custom icon if `osascript`/`SetFile` can make one (skip quietly otherwise).
4. **`tools/fixtures/disk-images.sh`.** Creates blank sparse images once, in `$CACHE/fixtures/disks/`, with `hdiutil create`: FAT32, exFAT, HFS+ (journaled), APFS and APFS case-sensitive, 256 MB each. `tools/fixtures/disk-images.sh clone <fs> <dest>` makes a copy-on-write clone (`cp -c`) for one test to attach. Follow the approach of the original's `packages/core/src/fs/testDiskImage.ts`.
5. **`tools/reference/README.md` and `tools/fixtures/README.md`.** Usage, in a few lines each.
