## Goal

The UI comparison pipeline of PLAN.md §5.4. One scenario file drives both the original Electron app and the native app into the same state, with the same fixture files, window size, preferences and frozen clock. Both sides then capture a screenshot and a geometry dump of named elements, and the tool compares them and writes a side-by-side contact sheet.

In P0 the pipeline only has to work end to end. The native app is still the spike, so large differences are expected and are reported, not failed.

## You own

- `Sources/FTAppKit/Automation/`, the in-app automation mode.
- `Sources/FTAppKit/AppDelegate.swift`, only to start automation mode from its flag.
- Minimal edits elsewhere in `Sources/FTAppKit/` to set `accessibilityIdentifier`s on existing views.
- `Sources/FTFoundation/AppClock.swift`.
- `tools/capture/`, `tools/pixeldiff/`.
- `Tests/FTAppKitTests/Automation/`.

## Do

1. **`AppClock`** (`FTFoundation`). `AppClock.now` returns `Date()` normally. When the environment has `FILETRAIL_NOW=<ISO-8601 local time>`, it returns that instant plus the time elapsed since launch. Later formatting code will use it.
2. **In-app automation mode**, compiled in `#if DEBUG` builds only. `FileTrail --automation <scenario.json> --out <dir>` runs the scenario's steps on the main actor, waiting for each to settle (pending navigation finished, run loop idle), then quits. Steps:
   - `window {width, height}`: content size in points.
   - `prefs {...}`: theme light/dark, accent, zoom, density, view mode, sort. Apply what the spike supports and log the rest as unsupported.
   - `open {path}`: navigate the front window.
   - `select {names}`, `key {key, modifiers}`, `command {id}`: command ids are the original's renderer command names (`docs/port/inventory/app-shell-and-tests.md` §1). Map the ones the spike has; log the rest as unsupported.
   - `wait {ms}`.
   - `snapshot {name}`: draws the window, frame view included (`cacheDisplay`, as `--snapshot` does), into `<out>/<name>.png` at 2× scale.
   - `geometry {name}`: writes `<out>/<name>.json`, listing every view with an `accessibilityIdentifier`. For each: identifier, frame in window content coordinates (top-left origin, points), and for text, the font size and weight, text color as hex, and the string value.

   A step that can't be done is reported in `<out>/report.json`; it doesn't crash or hang the run. Add a 30 s watchdog per step.
3. **Element names.** `tools/capture/elements.json` maps logical names to an Electron CSS selector and a Swift `accessibilityIdentifier`. Find the selectors by reading the reference renderer (`apps/desktop/src/renderer/components/*`, class names in `styles.css`). Give the spike's views matching identifiers. Start with:

   | Element | Element |
   |---|---|
   | window content | sidebar |
   | sidebar section headers | first sidebar row |
   | toolbar | title |
   | back button | view switch |
   | search field | list header |
   | first list row and its name cell | status bar |

4. **Electron driver** (`tools/capture/electron/driver.ts`, Bun with the reference's Playwright).
   - Launches the reference build from `~/Library/Caches/filetrail-port/reference/electron` with a fresh `--user-data-dir`. Before launch, seed `app-state.json` with the scenario's preferences; the format is in `docs/port/inventory/app-shell-and-tests.md` §2.
   - Freezes the page clock to the same `FILETRAIL_NOW` (Playwright `page.clock`), sets the window content size, and runs the same steps.
     - `open`: use the original's own navigation, for example its Go to Folder command or a launch folder argument.
     - `command`: send the command the way the menu does (`filetrail:command`).
   - `snapshot` is `page.screenshot` at device scale 2.
   - `geometry` dumps `getBoundingClientRect` and computed font, weight and color for the mapped selectors.
   - Reuse the original's e2e helpers where they help (`apps/desktop/e2e/`).
5. **Pixel diff** (`tools/pixeldiff/`). A Swift CLI compiled with `swiftc` into `build/pixeldiff/` (no `Package.swift` change). Takes two PNGs plus a mask JSON of rects to ignore, scales them to the same point size, and computes a per-region perceptual difference (CoreImage). Writes a heat-map PNG and a JSON score per region. Mask the traffic-light area and scrollbars by default.
6. **Runner** (`tools/capture/run.sh [--tier wp|wave|final] [--selftest] [scenario...]`).
   - Scenarios live in `tools/capture/scenarios/*.json`. The runner builds the debug app and runs the Electron and Swift sides.
   - Reference captures are cached in `~/Library/Caches/filetrail-port/captures/<referenceCommit>/<scenario-hash>/`, so the Electron side reruns only when a scenario changes.
   - It runs the geometry diff (±1 pt frames; exact font size, weight and color) and the pixel diff, then writes `tools/capture/out/contact.html`: per scenario, the two images side by side, the heat map, and a table of geometry deltas.
   - It prints one line per scenario, e.g. `scenario  geometry: 3/12 elements off (max 14pt)  pixels: 0.18  unsupported: 2 steps`.
   - Exit codes: non-zero on a pipeline failure. With `--tier wave` or `--tier final`, also non-zero on a geometry miss. In P0 the gate uses `--tier wp`, which only reports.
   - `--selftest` compares a capture with itself, which must be zero on both diffs.
7. **First scenarios.** Ten, using the `lighthouse` fixture (`~/Library/Caches/filetrail-port/fixtures/lighthouse/Lighthouse`) and `FILETRAIL_NOW=2026-10-13T14:38:00`, at 1200×760:
   1. List view of `app/src/components`, light
   2. The same, dark
   3. Icons view, light
   4. Sorted by size
   5. Sorted by date
   6. A selection of 4 items
   7. The `Lighthouse` root
   8. An empty folder
   9. Back after navigating
   10. Search field focused with text typed (Electron only, if the spike lacks it)
8. **`Tests/FTAppKitTests/Automation/`.** Unit tests for scenario parsing and the geometry dump format.
