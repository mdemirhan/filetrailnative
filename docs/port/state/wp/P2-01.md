## Goal

Reading folders, ported with the same results and faster: snapshot listing with sort and folders-first, tree children, path suggestions and resolve, item properties, the response-cache rules that behavior depends on, and the folder watch (FSEvents, 250 ms settle, at most 1 notification per second, >1000 names means "anything", missed-change check on window focus). The UI phases build on this API.

## You own

- `Sources/FTFileSystem/Listing/`, `Sources/FTFileSystem/Watch/`.
- `CFileTrail` additions for `getattrlistbulk` listing (a new `.c` file and header entries).
- Tests in `Tests/FTFileSystemTests/{Listing,Watch}/`.
- Bench additions in `tools/bench/` for listing.

## Port

| Original file | What |
|---|---|
| `packages/core/src/fs/explorerService.ts` | Snapshot, metadata, properties, tree, suggestions, resolve, sort |
| `apps/desktop/src/main/bootstrap/responseCache.ts` | The listing, tree and metadata cache parts only; folder-size parts go to P2-02 |
| `apps/desktop/src/main/folderWatch.ts` and the watch wiring in `apps/desktop/src/main/bootstrap.ts` | |

Same behavior first, per the preamble:
- Hidden means a leading dot.
- Bundles are detected by the extension list in `itemName.ts`; use P1-01's port if merged, otherwise the same list.
- Symlinks are classified as in `classifyEntry`.
- "/" is named "Macintosh HD".
- Sorting matches `compareEntries` (`localizedStandardCompare`, nulls last, folders first). Check it against goldens.

Read everything with `getattrlistbulk` (`native-and-system.md` §2), returning metadata with the listing. The API is an `actor DirectoryService` with async methods. Sorting runs off the main thread.
