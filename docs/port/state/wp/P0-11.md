## Goal

The code-derived behavior rules (`docs/port/behaviors/*.md`, ids `B-<AREA>-NNN`) count in the parity matrix the way `F-` rows do.

## You own

- `tools/parity-matrix/`, `docs/port/parity/`.

## Do

1. **`sync.ts`.** Read every `B-` id from `docs/port/behaviors/*.md`, so citing an unknown `B-` id is an error. Accept `B-` ids in Swift test comments and in scenario JSON (`behaviors: [...]`).
2. **`docs/port/parity/behaviors.tsv`.** Write it with the columns `id | area | improvement | tests | scenarios | status`. Status is `todo`, `partial` or `done`, with the same rules as features.
3. **`report.ts`.** Add a behaviors summary per area.
4. **`features.md`.** Add a `Behaviors` column linking each F row to the B ids that refine it, matched by the evidence file and topic. Leave it empty where no match is clear.

## Gate

- `bun tools/parity-matrix/sync.ts --check`
- `scripts/ci.sh`
