## Goal

Batch rename, inspected and carried out, ported exactly. P1-04 built the plan (`FTFoundation/BatchRename`), and the sheet is P6-03's.
- **Inspect** (`batchRenameInspect.ts`):
  - dates and folder names, hidden ones included;
  - date taken only when asked, through `DatesTaken.read` (P2-08);
  - grouped by folder;
  - the reasons an item can't be renamed (locked, folder can't be written);
  - bogus dates left out.
- **Execution** (`batchRenameExecution.ts`, file-operations.md §5.4):
  - levels deepest first, with a folder and the items inside it renamed together;
  - blockers moved aside under `.filetrail-rename-xxxxxxxxxxxx`;
  - swaps, chains and cycles;
  - a case-only change through a plain rename (`renamesItself`);
  - a taken name numbered (before the extension, or at the end for a folder, shortened by graphemes, giving up after 10,000), skipped or failed, as the setting says;
  - a blocker restored to its old name, or its old name numbered, or left hidden and reported;
  - stop rules; lock errors (`findLockedRefusal`).
- **Journal.** `batch_rename` entries, written once per level before any move and released after. Crash put-back: the old name, else the new one, else the old name numbered; unreachable entries kept. Add to P3-04's journal and recovery.
- **Coordinator.**
  - Prepare: leave out unchanged items ("Nothing would be renamed."), refuse duplicates and protected or system paths.
  - Report the kind; an unexpected error fails every item; a stop leaves the rest.
  - The undo record has the final names (P3-07's history takes it).
  - Fill `WindowWriteActions.batchRename` (P3-05). The sheet that calls it is P6-03's.
- **Plan ≡ run.** The run half of `batchRenamePlanAndRun`: the same numbering, swaps and chains, multi-folder, case-only, accents typed differently, and randomized agreement with P1-04's plan.
- **Differential.** Golden **`exec-batch-rename`**: the reference's inspect and execution on scenario trees, recorded with `tools/parity/exec` (tree, journal after each write, results, undo record). It includes swaps, cycles, case-only changes on case-insensitive and case-sensitive disk images, a stop at each level, and a crash at each journal write followed by recovery. The Swift engine must match it.
