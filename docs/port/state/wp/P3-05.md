## Goal

The write coordinator (bootstrap `writeOperations.ts`), ported exactly, and wired into the app.
- **One write slot for the app** (file-operations.md §3.6):
  - Paste, Copy To, Move To and Duplicate go through the Swift write service. Rename, New Folder, Trash and Delete (P3-06), Undo and Redo (P3-07) and batch rename (P3-08) plug into the same slot through one entry point.
  - Refusals read "Another write operation is already running." and "File Trail is quitting.".
  - `prepareWithReservedSlot` holds the slot during async prechecks.
  - On a terminal event, in this order: forget caches, record undo (a hook P3-07 fills), free the slot, tell the window.
  - An unexpected throw becomes a failed event.
  - `runWriteAlone` for recovery retries: not while busy, not during rename prep, not when quitting; it holds the slot and frees it on failure.
- **Progress** (§3.8): plain `running` updates at most every 100 ms (trailing timer, newest wins). Questions and terminal events go out at once and flush what is pending.
- **Windows** (§1.13):
  - every window gets the broadcasts, with items trimmed by `itemsForOtherWindows` (`WriteEffects`);
  - only the owner may answer or cancel, and analyses belong to their owner;
  - the analysis report sent to a window is trimmed (`trimAnalysisReportForWindow`);
  - when the owner window closes, the operation is handed to `ExplorerWindows.successor(ofExplorerWindow:)`. The handover carries `clearsCutClipboard` and only unanswered questions, and is adopted once. With no successor, the operation is cancelled.
  - The original's page reload and renderer crash cases map to window close; mark the ones with no native meaning N/A with a reason.
- **Quit and close while busy** (§1.12, app-shell-and-tests.md §3):
  - fill `QuitCoordinator.hooks.activeOperation` (a `BusyOperationKind`, which lives in FTAppKit: the coordinator in FTOperations reports its own kind and `AppDelegate` maps it) and `hooks.shutDown`: stop the operation (except Empty Trash), wait up to 15 s, count the Trash items not reached;
  - closing the last window during a write holds the close and asks "Stop and Close"; after Stop the operation is not handed on (`stoppedOnClose`);
  - every running `fd` and folder-size job ends at quit.
- **Caches.** Before a terminal event goes out, forget the `DirectoryService` cache and adjust folder sizes (`FolderSizeWrites`/`FolderSizeAdjust`) for the paths the write changed.
- **Startup recovery.** Open the journal and run P3-04's recovery before any window can write, then retry every 60 s through `runWriteAlone` while the journal has entries.
- **App side** (`Sources/FTAppKit/WriteOperations/`):
  - The `AppDelegate` makes one coordinator for the app.
  - Each window gets a `WindowWriteActions` facade with one method per action. Analysis, paste, Copy To, Move To and Duplicate work now; the UI flow around them is P5-08's. Rename, New Folder, Trash, Delete, Empty Trash, Undo, Redo and batch rename throw a clear "not available yet" until P3-06 to P3-08 fill them.
  - It has an observation API (an `AsyncStream` or callbacks) for progress, questions and results, which P5-08 connects to P5-09's progress card and toasts.
  - Route the write commands in `MainWindowController.perform` to it: undo, redo, rename, duplicate, New Folder, Trash, Empty Trash, cut, copy, paste, Move To.
  - Window-side busy state (B-CLIP §8, B-VIEW-183): another window's operation locks this one; the lock is released when the end was missed, with a notice that nothing ran; it is re-checked on coming to the front.
  - Early events (`earlyWriteOperationEvents.ts`) and other windows' results (what a window does with the trimmed items `itemsForOtherWindows` sends it; the original has only a test for this, `otherWindowsWriteResult.test.ts`).
  - After a write (B-CLIP §10): refresh, selection of what arrived (only in the tab where the operation started), and the tree selection remapped.
  - Dialogs: the refusal, busy and quit wording goes through a small `WriteDialogs` seam drawn as plain alerts with the original's exact text; P6-01 and P6-02 draw them later.
