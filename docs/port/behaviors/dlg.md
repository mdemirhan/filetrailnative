# B-DLG: Go To / Move To panel, Batch Rename sheet, Settings window, shortcut recorder, theme / accent / zoom, Help and About

What this area does better than Finder, in code terms (improvements A6, A9, A12, A15):

- Go To is a ranked, learning folder finder, not a path box: every folder opened is scored by kind of visit and age (visitScore, Firefox-style steps), words typed are matched in the name first and the path second with the matched letters marked, and a text starting with `/` or `~` switches to folder-by-folder path completion (Tab descends, a debounced 350 ms disk request). Move To is the same box with Return disarmed until a folder is actually chosen.
- Rename for several items is one pure plan (`planBatchRename`) that drives both the live preview and the rename itself: it settles name clashes (number, skip or hold), lets items swap names, compares names the way the disk does (case, accent encoding), and shows per item why it will not change.
- Settings is a separate window with five tabs whose every edit is persisted as a diff (only changed keys, 300 ms trailing debounce) and broadcast to the other windows; the shortcut recorder validates a key against the rules of the list, the menu and macOS before saving, and asks before taking a key from another command.
- Theme (Auto/Light/Dark), accent (9 presets plus any `#rrggbb`) and zoom (75 to 150) are applied to every window at once; accent tokens are derived so that white text on selections and buttons always reaches 4.5:1.
- Help is its own window that remembers its page, searches rows and shortcuts by words and by the key as written, and prints the keys the person has chosen, not the defaults.

## Open questions

- Reopening Go To after a session where the pointer moved: `lastPointerRef` is a ref of the always-mounted component and is not reset when the box closes, so the first mouse-move over the new list compares with the old position and may select a row at once (GTF:72, 466-475). Is that intended or only incidental to "pointer must really move"?
- Clicking a completion in path mode calls `setSelectedIndex(index)` after `setValue`, but the selection effect resets it to none in the same render because the mode is path (GTF:458-463, 157-163); the final selection after such a click is therefore probably "none". Not asserted by any test.
- In name mode a click on a row calls `onSubmit` even while `submitting` is true (the Open button is disabled then, the row is not guarded) (GTF:458-465). Possible double navigation; confirm whether to copy.
- Help's Escape: the shortcut list says "Esc: Return from Help" (HC:217), but the Help window (HWA) has no close-on-Escape handler and About uses `useCloseOnEscape`. How the Help window is closed with Escape (menu accelerator, or not at all) is not decided in the files read.
- The window-level "set zoom" and theme apply via different mechanisms in tests (jsdom) than in the app: `applyNativeAppearance` and `setZoomFactor` live in main.ts (MAIN:225-250, 640-657) and have no original unit test; the Swift port needs its own scripted check.
- Recording the plain Delete key assigns it (the refusal list does not include Delete, and "forward delete is allowed on its own", T-f2c50761), while Delete on a non-recording key removes it; confirm the Swift recorder should treat Delete as a recordable key.
- `describeRefusal` for "macOS" is also used for ⇧⌘/ although ⇧⌘/ is Help in macOS menus; the wording "macOS keeps ⇧⌘/ for itself." is kept as is (SH:834).
- Number fields in the Rename sheet drop non-digit characters including a minus sign and the decimal point; no maximum other than 9 characters (999,999,999 after sanitizing on load) is enforced while typing (BRS:952; BR:119).
- Inspection of dates taken happens on a different request than the first inspection (UBR:112-126); when it fails after the first succeeded, the error replaces the summary but the earlier plan stays visible (UBR:72-85). Confirm the intended preview during that state.
