# B-CLIP: Clipboard, paste review, drag and drop, write-operation states, Undo questions

What this area does better than Finder, in code terms (improvements A3, A4, A5, A17):

- The clipboard is a visible object: a toolbar button with a count, a list grouped by source folder where items can be revealed or removed one by one, a copy/cut mark and flash on the rows, and cut items dimmed. The clipboard follows the app's own renames, moves, trashes, Replaces and Undo, and drops items other apps took away, so a later paste still finds them (`lib/copyPasteClipboard.ts`).
- Paste is checked before it runs: a "Preparing" sheet, then a review sheet only when something already exists. Safe defaults (Skip everything), "For all conflicts" buttons, per-row choices, plain-language row details, a red Replace that Return never triggers, and an alert for a single clash (`lib/copyPasteReview.ts`, `CopyPasteReviewDialog.tsx`). Things that change while it runs ask again (`CopyPasteRuntimeConflictDialog.tsx`).
- Drag and drop follows Finder's disk rules from the disks' real answers (not just paths), supports springing into folders, tab hover, drags from other apps with the same rules, and puts springing tabs back afterwards (`useExplorerDragAndDrop.ts`, `lib/internalDragAndDrop.ts`).
- One write operation at a time for the whole app, with a delayed progress card, one dialog wording for every refusal, results as a sheet only when something needs reading, and Undo/Redo that ask all-or-nothing questions with the safe answer as default (`useExplorerActions.ts`, `lib/undoQuestion.ts`).

Conventions: all paths under Evidence are relative to `apps/desktop/src/renderer/` in the original (pinned e4d0872) unless they start with `packages/`. Test ids come from `docs/port/parity/tests.tsv`. "Original" = the Electron app. Timings are milliseconds. A "write lock" means `writeOperationCardState !== null || foreignWriteOperation !== null`.

## Open questions

1. Marks setting: the comment in `lib/clipboardMarks.tsx:15` says the folder tree and the file list are switched on/off separately in Settings, but `App.tsx:797` uses one preference (`markClipboardItems`) for both. Which is intended for the port?
2. Is the pasted selection scrolled into view? `useExplorerNavigationController.ts:925-954` only sets the selection (anchor first, lead last); any scroll-into-view of the lead item comes from generic selection code outside this area's files.
3. `reviewLargeBatchWarning` is accepted by `startMoveToDestination` and `startCopyToDestination` but no production caller sets it, and the paste path (`analyzeCopyLikeRequest`) reviews only on conflicts. So the "This is a large operation (N items in total)" review variant and the `large_batch` warning appear unreachable in production; tests only prove the drag path does not review a large batch alone (T-f81ebbab). Port as dead path or drop?
4. A cut paste clears the clipboard when `completedItemCount > 0` even if other items failed, were stopped, or were skipped; those items then are no longer on the clipboard (only reachable via the result sheet's Retry). Confirm this is intended behavior to copy.
5. Whether a paste into a folder shows its selection when the pasted folder reload races with another tab/window can't be fully derived from the files; only `startedInTabOnScreen` is decided here.
6. `describeDragRefusedWhileBusy` uses a straight apostrophe ("Can't drag while …") while all other texts use the curly one; copy exactly or normalize?
7. The "Show Clipboard" menu command opens the clipboard menu anchored under the toolbar button; if the toolbar button is hidden by toolbar customization the anchor rect is missing (menu does not open since `menuStyle` stays null). Behavior with a customized toolbar is not covered by a test.
8. Window inactive: the clipboard menu closes on window `blur`; other inactive-window states (drag over an inactive window, progress card while inactive) are only covered indirectly (`document.hasFocus()` for bring-to-front, `visibilityState === "hidden"` for the drag check). No rule was written for inactive-window row colors of marks.
