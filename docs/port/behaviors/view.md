# B-VIEW: Views and window chrome

Source: original at `/Users/tcmudemirhan/src/tsproj/filetrail` (pinned `e4d0872`), paths relative to `apps/desktop/src/renderer` unless noted. Rules come from the code and its tests, not from the README. Improvements covered: A10, A13, A14, A15, A17.

What this area does better than Finder, in code terms:
- Three views read their sizes from token modules (`iconGridLayout`, `detailsLayout`, `flowListLayout`), never from the DOM: virtualization, keyboard stepping, paging, drag-to-select hit tests and reveal-into-view all use the same numbers, so only the rows on screen are mounted. Each of the three views has its own regular and compact density.
- The List (table) fits its saved columns into the pane (Name shrinks to 160 px, then columns fall away from the right, saved widths untouched), fits a column to its content on a divider double-click, shows relative dates, octal permissions and size bars behind the sizes when sorted by Size.
- The toolbar is one row of capsules in a user-chosen order; it measures items and moves the last removable ones into a `»` menu instead of clipping, and is customised in place by dragging (handles, palette, keyboard moves).
- Tabs hold a full snapshot per tab (folder, history, selection, scroll, search that keeps running in the background, hidden/folders-first, sidebar), restore it before paint, follow renamed folders, and can be dragged, merged between windows and reopened.
- The folder on screen is watched: outside changes are merged into the list quietly (selection, search results and tree stay), held back while the user is mid-edit, a menu is open or an operation runs.
- Menus list only what can be done to the clicked items; notifications are passive and stack above the status bars.

Terminology: in the code `viewMode` `"icons"` is Icons, `"details"` is the table called **List** in every menu, and `"list"` is **Compact List** (names in columns that scroll sideways). Menus order them Icons, List, Compact List. Shortcuts: Cmd+1 Icons, Cmd+2 List, Cmd+3 Compact List (`shared/shortcuts.ts:376-390`).

## Open questions

- `components/ExplorerWorkspace.tsx:1198` comments "Search results are one table, whatever the folder's view" on the view switch, but the code keeps a separate `searchViewMode` and the switch writes to it in search mode, and the switch is only disabled by dialogs. The comment looks stale; the Swift port should follow the code (separate search view mode). Confirm with a scripted run in the built copy.
- The Sort button comment (`ExplorerWorkspace.tsx:1237`) says choosing the active field again reverses the direction, but the code does nothing for the active field (`if (value !== sortBy)`) and reverses direction only via the Ascending/Descending radios. Rule written from the code. Header clicks and Cmd-menu sort commands do reverse on a repeat.
- `Reopen Closed Tab` reopens a tab with mode "load" (reads the folder afresh, selection lost) while `toReopenableSnapshot` keeps the view settings; whether the scroll position is meant to be lost is not stated anywhere.
- It is unclear whether `INITIAL_APPLICATION_MENU_STATE.viewMode = "list"` (Compact List ticked) is intentional before the first report; it is visible only for the instant before the window reports.
- Tab hover switch (700 ms) and spring-loading (700 ms) share constants in `useExplorerDragAndDrop.ts`; this file did not read the drag-and-drop rules in full, so only the tab-related ones are written here.
- `describeTab` uses the tab's live `searchRunning` (status "running"), but a background tab's `searching` flag comes from the snapshot's search status, which is only refreshed every 1000 ms; the exact moment the animation stops for a background tab was not tested.
- The overflow `»` menu hard-codes "Folders First" for that toggle while its tooltip says "List Folders First" / "Mix Files and Folders" depending on state; both are written as found.
- Tests in `App.tabs.test.tsx` about remapped shortcuts (T-5c7904a9, T-47b5d059, T-e3c189ac) and in `App.commands.test.tsx` about copy/paste, Move To, Rename, New Folder, Duplicate and startup restore (for example T-574fdd65, T-0804a6c2, T-fbbe09e1) are about the shortcut-settings, file-operation and navigation areas; they were not written as rules here beyond the dialog gating that touches the window chrome.
