A change that goes against one of them needs the owner's yes first; [principles.md](principles.md) says how a decision is weighed, and when to ask about making an exception or relaxing one. ## The standing decisions

- **The minimum macOS is 26.** There are no fallbacks for macOS 14 or 15, and the Liquid Glass look is the only one built.
- **Matching the earlier app pixel for pixel is not a goal.** Prefer the system's controls, symbols and look. Code, tests and goldens that existed only to match the earlier app's stylesheet or layout are gone.
- **The system's look.** Tabs and toolbars use Liquid Glass. Commands use SF Symbols, Finder's where Finder has the command. Sheets, the Info panel and Settings use the system's checkboxes, pop-up buttons, switches, number fields and tables.
- **Controls in the content are rounded rectangles; capsules are the toolbar's.** On macOS 26 the system draws a control's shape by its size: small and regular are rounded rectangles, large and extra large capsules. Segmented controls, buttons, pop-ups and fields in the panes' bars and in sheets are the regular size, 24 pt, so a row of them shares one shape and one height: the search scopes, the Rename sheet's modes and the paste review's "For all conflicts" are regular segmented controls (they were large, capsules beside rounded fields), the results filter's Fuzzy/Contains chip has the small radius inside the field's corners, and the search bar's Done and Stop and the Trash bar's Empty are 24 pt. The selected segment keeps the accent. The toolbar's groups and search field stay capsules, as Finder's are. Decided 2026-11-15.
- **Nothing is read before it is needed** (the owner, 2026-11-20). An item's details beyond what its listing or search result gives (dates, sizes, tags, Date Last Opened) are read only when something on screen needs them: a column shown reads them for the rows on screen; an order or groups by them read them for every item, and only while that order or those groups are chosen, and only the one field they need. Nothing is read ahead in case it is asked for. Speed is not given up for a feature unless the feature needs it. Search results order and group by name, folder and kind from what fd gives, and by any other field only through such a read.
- **Font sizes and row heights are the app's own, not Finder's**: sidebar 14 pt, icon labels 13, list 14, path bar 12. From Finder the app takes the Favorites and Locations icons as system symbols, the Locations icon color, the unfocused selected fill and the toolbar's sizes. Favorites icons use the app's accent, not the system's, and the search field keeps its own 200 pt width rather than Finder's.
- **Dark mode uses Finder's colors.** The content's background is the system's content material, so it takes the desktop's tint as Finder's does. The path bar is 3.3% white lighter and the sidebar's gray selection is 13.5% white, both measured from Finder. Light mode is unchanged.
- **Glass goes on brief surfaces only.** Toasts, the progress card, plain alerts (a title, a message and buttons) are glass, and keep their edge and shadow so they read over a white pane. Go To and Move To, the paste review, the Rename sheet, the path bar's suggestion list, and alerts with a list or a field stay opaque. The system's own sheet is opaque and its alert is glass, and glass behind lists and fields lets colorful content smear behind the text.
- **The Info panel is a plain split item**, not the system's inspector item. The toolbar lays its material over plain items only; as an inspector the panel's own color showed through the toolbar in dark mode.
- **File Copy, Cut and Paste use the app's own clipboard**, the one the toolbar's clipboard button lists, not the system's. What this means for people is in known-issues.md. Copy Path puts text on the system's clipboard, and Copy Contents a file's image or text.
- **Batch rename's regular expressions are `NSRegularExpression`'s.** The pattern is handed to it as typed (`RenamePattern.swift`): `\d`, `\w`, `\s` and `\b` are Unicode's, case folds as ICU does, ICU's syntax is what is accepted, and a pattern it can't read says only "The pattern isn't valid.", as the system says no more. `$1`, `$&`, `$<name>` and `$$` (`expandReplacement`), named groups, Match case and the 50 ms a name stay; plain-text Replace Text still matches letter by letter. Changed on 2026-11-20: it replaced a translator that kept JavaScript's rules (664 lines), which the owner judged not worth its size for a Rename sheet. JavaScript-only syntax (`\u{…}`, `[]`, `[^]`, `\0`) is now refused, and a saved preset that holds it says so. Added on 2026-11-20: beside the 50 ms a name, a pattern gets a quarter of a second for all the names together and 10 µs more for each character of them (`RenamePattern.timeForAllNames`, `timePerCharacter`), in the CPU time of matching; past that the sheet says the pattern takes too long and renames nothing, as it does past the 50 ms. The sheet matches every name again at each change of its settings, so names that each stayed under 50 ms were all matched: 200 names at 36 ms each kept it for 7 s at every key typed. The limit grows with the names' length because an ordinary pattern's time does: over 50,000 names the ordinary patterns measured took at most 1.8 µs a character.
- **The search-result highlight uses `NSRegularExpression` for Regex searches**, as batch rename does. The search itself is fd's, with Rust's regex. Plain Text is marked by the app's own matcher (see "Typing finds names by their letters in order").
- **VoiceOver is not a supported target.** Don't add accessibility work; the VoiceOver-only code is gone. Accessibility identifiers and `accessibilityPerformPress()` stay, as the tests press things through them.
- **There is no import or upgrade path from the earlier app.** The earliest release of this app is v0.8.0, and its bundle id is `com.filetrail.native`. Nothing reads files only the earlier app wrote.
- **A window holds at most 25 tabs.**
