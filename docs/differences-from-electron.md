# Differences from the Electron app

Each entry is an intentional difference between this app and the Electron app it was ported from.

| ID | Area | Original | Native port | Why | Status |
|---|---|---|---|---|---|
| D-001 | Tabs | In-window tab strip in the app's colors; tab context menu has Duplicate Tab | System tab bar in the system's own look (Liquid Glass on macOS 26 and later, classic on older); Duplicate Tab only in the File menu and its shortcut | Native window tabs chosen on 2026-10-13; the system's look over the original's colors, user decision 2026-10-30 (P5-23) | approved (decision) |
| D-002 | Tabs | Middle-click closes a tab | Not available; ⌘W or the tab's close button | The system tab bar owns tab clicks | approved 2026-10-13 |
| D-003 | Tabs | Hovering a file drag over a tab for 700 ms switches to it; dropping files on a tab moves or copies them into its folder, with the tab showing it as a drop target | Not available, neither the hover nor the drop: a drop on a tab does nothing | The system tab bar owns drags over tabs and takes no file drops | approved 2026-10-13 (the drop added 2026-10-30, P7-03) |
| D-004 | Drag | `system:readDragChangeCount` throws (addon export missing), so the "same drag came back" check never runs | The check works, using `draggingSequenceNumber` | A bug in the original, not a behavior | approved 2026-10-13 |
| D-005 | View | Whole-window zoom 75–150% (View › Zoom In/Out/Actual Size, ⌘+ / ⌘− / ⌘0, a zoom setting in Settings) | Not available; the UI is fixed at the original's 100% metrics. The `zoomPercent` preference is still read when importing settings and is ignored | Decided by the user on 2026-10-13: not worth the complexity | approved 2026-10-13 |
| D-006 | Batch Rename | Regex patterns run on JavaScriptCore; an invalid pattern's message is the engine's text | Patterns run on `NSRegularExpression` after translation (`JSRegExp`). The text after "The pattern isn’t valid: " is the port's own wording. A few edge cases still differ: a back reference to a group that took no part fails instead of matching empty; `\P{Lu}` under `i`; captures of empty loops such as `(a*)*`; look-behinds of unbounded length; a ligature like ﬁ in a character class also matching "fi" | No JavaScript regex engine in the system frameworks; whether a pattern is valid matches on every tested pattern (P1-04) | approved 2026-10-14 |
| D-007 | Settings | A saved text setting cut at 255 UTF-16 units inside an emoji keeps half the surrogate pair | The broken half becomes U+FFFD | A Swift string cannot hold a lone surrogate (P1-04, P2-07) | approved 2026-10-14 |
| D-008 | Paste | Keep Both with a copy number of 2^53 or more on a taken name loops forever | Stops after a bounded number of attempts and reports that no free name was found | A hang in the original, not a behavior (P1-05) | approved 2026-10-14 |
| D-009 | Folder sizes | Finished folder sizes are polled every 200 ms | They arrive as soon as they finish, at most every 20 ms; the sizes are the same | Native worker notification replaces polling (P2-02) | approved 2026-10-14 |
| D-010 | Trash | An Empty Trash error reads like `0:46: execution error: … (-1712)` (osascript) | Reads `execution error: … (-1712)`, without the source-range prefix | NSAppleScript instead of the osascript tool (P2-05) | approved 2026-10-14 |
| D-011 | Search | Match highlighting uses JavaScript regex semantics | Highlighting runs on `JSLegacyRegExp`, the port's own engine for JavaScript's regex syntax, on the system's regex underneath | No JavaScript regex engine in the system frameworks; the interim on plain `NSRegularExpression` (P2-06) ended when search moved to it (P5-07) | approved 2026-10-14; no longer interim |
| D-012 | Menus | Full screen is a hidden menu item with ⌃⌘F | AppKit's own View › Enter Full Screen item, same key | Native apps get it from AppKit; hiding it fights the system (P4-01) | approved 2026-10-14 |
| D-013 | Tabs | Tabs can't be dragged between windows or out into a new one | The system tab bar allows both; the port turns a dragged-out tab into a full explorer window and merges a dropped tab into the target window | Native window tabs (D-001) own tab drags (P4-02) | approved 2026-10-14 |
| D-014 | Windows | The window's title is the front tab's label, so the Window menu, ⌘\` and Mission Control show labels like "fixtures — filetrail-port" or “q” in src | The Window menu and the Dock's window list show the tab label; Mission Control and the accessibility title show the folder name, which is also the toolbar title | With native tabs, `NSWindow.title` is the toolbar title too (P4-02) | approved 2026-10-14 |
| D-015 | Toolbar | The app draws its own 52 pt toolbar band (the window background with a 1 pt line under it) and its items on round capsules; the traffic lights sit 14 pt in and 16 pt down; with the folder tree hidden the first item starts 76 pt from the window's left; the buttons are 32 pt, 9.5 pt below the band's top; the view switch, search field and clipboard button are drawn by the app; » is a button of the app's that opens its own menu, listing toggles, `as Icons…`, `Sort by …` and theme choices inline, and the removable items nearest the end go to it first | A unified system toolbar (NSToolbar, as Finder), with one system item per command: the system draws the band and each item's Liquid Glass, in its own look and not the original's colors, 52 pt high on macOS 27, and puts side-by-side buttons on one glass platter, the view switch and search field on their own (the original's capsules, read from the running toolbar: `theSystemsPlattersAreTheOriginalsCapsules`), so no `NSToolbarItemGroup`, which the user could only drag as a whole, where the original's capsules follow the order; the original's Space is the system's space item. The traffic lights are where the system puts them (19 pt in, 19 pt down on macOS 27); the buttons are 36 pt, 8 pt below the band's top; the items start after the sidebar's edge, or after the traffic lights with the tree hidden. Icons, order, commands, enabled states and tooltips stay the original's. The view switch is an `NSSegmentedControl` (its tooltips are the system's; its segments 34 pt wide as Finder's, where the system's own fit is 30), search an `NSSearchToolbarItem` (the system's field, its magnifier opening the same options menu; the ✕ is the system's button, with the original's tooltip, name and trimmed-text rule), the clipboard button a system button with its count. » and its menu are the system's: which items go first is the system's choice (required items last), and the view, sort, theme and View Options are submenus, as it holds one entry per item. A toggle that is on shows the system's pressed look, a gray pill as on Finder's selected view, rather than only a darker icon (the button's real on state fills it with the accent color). Display modes are off. As Finder's, the band and the content have the system's background (the panes that shared the original's --bg-base in the content column too; file rows, icons and labels stay the original's) and the title the system's label color, dimmed to Finder's gray in a key window and the tertiary label color in a window that is not key. The band has no line of its own; while the pointer is over the band one thin line (one device pixel, the system separator color, as Finder's) shows under it, across the content column. The app draws that line with a tracking area, since the system's own comes with a scroll view reaching under the toolbar | User decisions 2026-10-14 (use NSToolbar, so the system tab bar sits over the content column only, P5-11) and 2026-10-30 (real system items with Liquid Glass over the original's band colors and capsules, P5-23, P5-24; the chrome follows Finder, P5-27, P5-28) | approved 2026-10-30 |
| D-016 | Toolbar | Customize Toolbar edits the row in place: a 35% veil over the window, a handle on each item, a panel 8 pt under the band with its own title, note, Restore Defaults and Done, drag ghost and red removal state, and keys (←/→, ⌥←/⌥→, Delete, Esc). A right-click on an item does nothing (Back and Forward: their history); on the title or the empty room it offers a one-item Customize Toolbar… menu | The system's: Customize Toolbar… (the menu bar, View Options, or the system's right-click menu on the toolbar, on items too except Back and Forward, which keep their history, and which do nothing while dimmed) opens the system's sheet on the window, about 933 × 734 pt on macOS 27 (taller than a short window; AppKit's own size), with its words, its default set for Reset, and Done; ⌘-drag moves or removes items without the sheet. No veil, handles, panel, ghost or keys of ours. `topToolbarItems` stays the source: what changes goes to the preference, so saved layouts, imports and Reset to Defaults work as before and every tab follows. The system can't keep an item movable but not removable: a required item (title, clipboard, search, View Options) taken off comes back at the end. The clipboard item, hidden while empty, shows in the sheet | User decision 2026-10-30 (system customizing in place of ours, P5-24) | approved 2026-10-30 |
| D-017 | Sidebar | The sidebar is the sidebar color at 62% over the window's vibrancy, up to a 1 pt hairline in the middle of the 8 pt gutter, with the gutter's other half the window's color | The sidebar split item's own material with nothing over it (Liquid Glass on macOS 26 and later), as Finder's, in every appearance. Its edge is one straight line where the item ends, 8 pt past the tree, with no hairline: the 8 pt gutter is the sidebar's, and under the pointer it shows the accent's line on the edge. The content and the rows that reached the hairline start at that edge | The sidebar is a system sidebar split item, which brings its own material (P5-11); user decision 2026-10-30: the chrome follows Finder, whose sidebar meets the content with no line (P5-27) | approved 2026-10-30 |
| D-018 | Paste | "Preparing to Paste…" (and Move, Copy, Duplicate) shows at once for every copy-like write, even a tiny one | It shows only if the analysis is still running after 500 ms, and then stays at least 300 ms. Cancel stops the analysis whenever it is up | The dialog flashed up and away on small pastes; requested by the user 2026-10-30 (P5-16) | approved 2026-10-30 |
| D-020 | Controls | Push buttons, switches and segmented controls are drawn in the app's own look: 28 by 16 switches and selection in the accent you pick. The Info panel is a pane of the content's grid | The system's `NSButton`, `NSSwitch` and `NSSegmentedControl`, in the system's look on macOS 26 and later (Liquid Glass): hover, press and focus ring are the system's. Keys, Tab order, labels, sizes and disabled states are as before; default buttons and selected segments still take the chosen accent, switches take the system's accent (a switch has no tint of its own) and are the system's mini size, 36 by 16. The Info panel is the system's inspector item: same contents, limits, command and remembered width and state, with the app's own 8 pt resizer and the same slide; the column under the band beside the panel is the inspector's, which the toolbar's row and the tab bar reach over | Use the system's controls for Liquid Glass, user decision 2026-10-30 (P5-26) | approved 2026-10-30 |
| D-019 | Dialogs | Go To Folder and the other sheets start 60 pt below the window's top, over the tab strip | While the system tab bar shows, a sheet starts that much lower (36 pt on macOS 27), under the bar | The system's title bar lies over the window's content, so the bar would hide the sheet's top (P5-23) | approved 2026-10-30 |
| D-021 | Sidebar | Favorites and Locations have the original's line icons, Favorites in the accent you pick, Locations in the neutral icon color; a selected row without the keyboard is `--bg-active-inactive` (#dcdce1, #2a2d36) | System symbols as Finder's (the same 16 pt, 14 pt when compact; the Settings › Favorites picker shows the same symbols, fitted to its boxes, and saved icon preferences keep their meaning; Macintosh HD is `internaldrive`, other disks `externaldrive`, network shares `network`), Favorites still in the accent you pick, Locations in the system's secondary label color. The system's unemphasized selection color doesn't give it (opaque #dcdcdc against Finder's #d7d7d8). A wide symbol sits centered over the 16 pt box. Rows' widths, the headings' line icons in the chosen accent, the folder tree's icons, the focused selection and other panes' selection stay | User decision 2026-10-30, comparing with Finder (P5-28) | approved 2026-10-30 |
| D-022 | Menus | The toolbar's menus, Back's and Forward's history, Open With in the Info panel, the path bar's folder menu, Search's options and Settings' app menu are drawn by the app; the clipboard list and the favorite icon grid are panels drawn in the window | They are the system's: `NSMenu` and `NSPopover`, in Liquid Glass, with the same items, order, checks, disabled rows, icons, marks and the Option swap to Always Open With. What a system menu does differently: it has the keyboard while it is open, so a key Search's options has no use for no longer goes on to the search field and Return with nothing marked closes the menu without running the search; Tab and keys with ⌘, ⌃ or ⌥ don't close a menu, type-select is the system's, and the path bar's list can be as tall as the screen instead of 440 pt, opening with the ticked folder at the button when it doesn't fit above it; a slow folder's list closes "Loading…" and comes up in its place, since a system menu can't move while open. No window is resized under an open menu, so Sort has nothing to follow | The user's decision (2026-10-30): system controls get the system's look | approved 2026-10-30 |
